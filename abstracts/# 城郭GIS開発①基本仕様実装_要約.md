# 城郭GIS開発① 基本機能・CS立体図試験実装　引き継ぎ要約

## ① このチャットの目的

和歌山県内の城館研究を支援するWeb GIS「城郭研究支援GIS」の基本機能を実装し、将来的な公開に向けた技術的な基盤を作ることを目的とした。

主な目標は以下。

* Leafletを利用したWeb地図の構築
* 地理院標準地図の表示
* 城館データ（GeoJSON）の表示
* 城館・類似地点等を分類してマーカー表示
* 地図上から経緯度を取得する機能
* 和歌山県公開の3次元点群データからCS立体図を作成できるか検証
* 作成したCS立体図をXYZタイル化し、Web GIS上で表示できるか検証

このチャットで、Web GISの基本機能と「点群→DEM→CS立体図→XYZタイル→Leaflet表示」の一連の技術検証まで完了した。

---

## ② 実装・変更した内容

### Web GIS基本部分

VS Code上の `castle-gis` プロジェクトでLeafletを使用した地図を作成した。

基本構成は以下。

```text
castle-gis/
├── css/
│   └── style.css
├── data/
│   └── castle.geojson
├── js/
│   └── main.js
├── leaflet/
├── tiles/
│   └── 06TD141_tiles/
├── index.html
├── LICENSE
└── README.md
```

地理院標準地図を背景地図として設定。

主な設定：

```javascript
minZoom: 5
maxZoom: 18
```

Leafletのレイヤー切替コントロール、縮尺表示を実装した。

### 城館データ表示

Excel原本からGeoJSONを作成し、

```text
data/castle.geojson
```

として配置。

分類に応じてマーカー色を変更する仕様を実装。

* 城館：赤
* 非城館（後に「類似地形」へ名称変更予定）：青
* 調査中：黄（gold）

マーカーには視認性向上のため黒い枠線を付けた。

```javascript
L.circleMarker(latlng, {
    radius: 8,
    color: "black",
    fillColor: color,
    fillOpacity: 0.8,
    weight: 2
});
```

ポップアップは情報過多を避けるため簡潔にし、城館名を中心に表示する方針とした。

### 凡例

画面右下に、

* 城館
* 非城館／類似地形
* 調査中

の凡例を実装した。

### 座標取得機能

地図をクリックすると、その地点の座標を取得できる機能を実装した。

表示順は、

**経度 → 緯度**

に統一。

コピー時も、

```text
経度[TAB]緯度
```

というタブ区切り形式にし、Excelへ直接2列として貼り付けられるようにした。

座標取得用途に合わせ、地図上のカーソルも通常の手形ではなく、狙いやすい十字線に変更した。

### QGIS導入

macOSへQGISをインストール。

CS立体図作成用として、

**CSMap Plugin**

をインストールした。

CSMap Pluginは通常の「プラグイン」メニューではなく、

```text
プロセシングツールボックス
→ CSMap Plugin
→ DEMをCS立体図に変換
```

から使用する。

---

### 和歌山県3次元点群データの利用試験

和歌山県統合型GISから、古座川町・大柳周辺を含むメッシュ

```text
06TD141
```

を選択。

「グラウンドデータ」をダウンロードした。

使用ファイル：

```text
06TD141_grd.txt
```

約166.8 MB。

QGISの「CSVテキストレイヤを追加」で読み込んだ。

データは4列構成。

```text
field_1
field_2
field_3
field_4
```

読み込み時に先頭行をフィールド名として扱わないよう設定。

座標系：

```text
EPSG:6674
JGD2011 / Japan Plane Rectangular CS VI
```

設定：

```text
X値：field_2
Y値：field_3
Z値：field_4
```

`field_4` は標高。

読み込み結果：

```text
PointZ
約4,716,011点
```

正常に読み込めることを確認した。

---

### 1 m DEM作成

QGISの

```text
プロセシング
→ 内挿
→ TIN内挿（不規則三角網）
```

を使用。

設定：

```text
入力：06TD141_grd
Z座標を使用
内挿方法：線形
ピクセルサイズ：1.0 m × 1.0 m
```

出力：

```text
06TD141_dem_1m.tif
```

約2 km × 1.5 kmの範囲で、約1501 × 2001セル。

処理時間はMacBook Air上で約2分38秒だった。

---

### CS立体図作成

CSMap Pluginで、

```text
06TD141_dem_1m.tif
```

を入力し、CS立体図を作成。

出力：

```text
06TD141_CS.tif
```

CS立体図として正常に地形が表示され、尾根・谷・斜面上の微地形を判読できることを確認した。

---

### XYZタイル生成

QGISの

```text
XYZタイルを生成（ディレクトリ）
```

を使用。

最終的な設定：

```text
領域：06TD141_CS
最小ズーム：12
最大ズーム：18
DPI：96
形式：PNG
タイルサイズ：256 × 256
TMS：OFF
```

出力：

```text
06TD141_tiles/
├── 12/
├── 13/
├── 14/
├── 15/
├── 16/
├── 17/
└── 18/
```

通常のXYZ形式

```text
{z}/{x}/{y}.png
```

になっている。

重要事項：

XYZタイル生成時には、QGISで

```text
☑ 06TD141_CS
☐ 06TD141_dem_1m
☐ 06TD141_grd
```

のように、**CS立体図だけを表示した状態でタイル生成する必要がある。**

他のレイヤーを表示したまま生成すると、非常に暗い不正なタイルになることを確認した。

---

### LeafletへのCS立体図実装

生成したXYZタイルを、

```text
castle-gis/tiles/06TD141_tiles/
```

へ配置。

`main.js` に以下のようなCSレイヤーを追加した。

```javascript
const csMap06TD141 = L.tileLayer(
    "./tiles/06TD141_tiles/{z}/{x}/{y}.png",
    {
        minZoom: 12,
        maxZoom: 18,
        maxNativeZoom: 18,
        opacity: 1.0
    }
);
```

地理院標準地図の上にCS立体図を重ね、その上に城館マーカーを表示する構成とした。

最終的に、

```text
地理院標準地図
    ↓
CS立体図
    ↓
城館等マーカー
```

という3層構造で正常に表示できた。

右上のレイヤー切替からCS立体図のON/OFFも可能。

## ③ 確定した仕様・方針

### Web GIS

* Leafletを使用。
* 背景地図は地理院標準地図。
* 城館情報はGeoJSONで読み込む。
* 城館情報は背景地図・CS立体図より上に表示。
* マーカーには黒枠を付ける。
* 地図クリックによる座標取得を実装。
* 座標順序は「経度 → 緯度」。
* コピー形式はタブ区切り。
* 地図カーソルは十字線。

### データ管理

Excelを城館データの原本とし、そこからGeoJSON等を生成する方向。

GitHubリポジトリ：

```text
castle-gis
```

を開発コードの正本とする。

作業単位ごとに、

```text
コミット
→ Push
→ git status -sb
```

を行い、正常状態を保存してから別系統の作業へ移る。

現段階ではGitブランチは使用せず、こまめなコミットで管理する。

### CS立体図

基本工程：

```text
和歌山県グラウンド点群
↓
QGIS
↓
TIN内挿
↓
1 m DEM
↓
CSMap Plugin
↓
CS立体図GeoTIFF
↓
XYZタイル
↓
Leaflet
```

この工程が実際に成立することを `06TD141` で確認済み。

現時点の標準DEM解像度は **1 m**。

ただし0.5 m DEMについても今後比較検討する価値がある。

Web用XYZタイルは、

```text
Zoom 12～18
PNG
256 × 256
XYZ形式
```

を当面の標準とする。

## ⑤ 未解決事項・積み残し

### CS立体図関係

1. **1 m DEMと0.5 m DEMの比較**

城郭遺構の判読性が0.5 mで明確に向上するか未検証。

0.5 m化による、

* データ容量増加
* タイル数増加
* 処理時間増加
* ノイズ増加

とのバランスを確認する必要がある。

2. **隣接メッシュ接続試験**

現状は `06TD141` の1メッシュのみ。

次は隣接メッシュを追加し、

* CS立体図同士が自然につながるか
* 境界線が目立たないか
* DEM作成条件を統一できるか

を確認する。

3. **全県展開方法**

1メッシュずつ手動処理する方法では作業量が大きいため、

* 点群→DEM
* DEM→CS
* CS→XYZ

の半自動化・一括処理を検討する。

4. **CSタイルの保存・配信方法**

1メッシュでは問題ないが、全県化するとPNGファイル数・容量が非常に大きくなる。

GitHubリポジトリに全タイルを置く方式が適切かは未決定。

将来的には別のタイル配信方法を検討する必要がある。

5. **メッシュ境界**

現在の1メッシュだけでは、CS立体図と地理院地図の境界が四角く明瞭に見える。

隣接メッシュ追加時に改善するか確認する。
